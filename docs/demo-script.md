## 一句話

上班族在松山車站按一下，平台替他配一台剛好要開進內科、還有空位的私家車；駕駛開車時只需要按「確認」。

## 角色與畫面

| 角色 | 帳號 | 在哪裡操作 | 給誰看 |
|---|---|---|---|
| 台上的駕駛 | `driver4` | 展示頁左邊的手機 | 觀眾 |
| 乘客 | `passenger1` | 展示頁右邊的手機 | 觀眾 |
| 另一位真人駕駛 | `driver5` | 台下腳本 `just demo-offstage` 自動操作 | 不給觀眾看，收到請求就自動「婉拒」 |
| 模擬車 | `driver1`～`driver3` | 同一支腳本在背景開模擬器 | 不給觀眾看 |

講者只操作展示頁上的兩支手機；台下的事交給腳本，終端機會提示講者兩個時機。

- 展示頁：`http://localhost:5170`。兩支手機都是 390px 寬，右上角有「重設」。
- `driver4`、`driver5` 都在「我的標籤」帶「女性友善」；模擬車都沒有。乘客把「女性友善」設成「強制」，請求就只會配給台上的兩位真人駕駛。
- `driver4` 帶入上次的設定：松山車站 → 瑞光路 513 巷、可載 3 人、不自動接受。`passenger1` 帶入常用目的地瑞光路 513 巷，以及可接受的公車站「瑞光港墘路口」「港墘路」。

## 事前準備

當天早上做一次，換機器時重做。

1. 根目錄 `.env` 要有：
   - `MAP_API_KEY`：後端用 Google Routes 算真實路線。
   - `VITE_GOOGLE_MAPS_API_KEY`：瀏覽器顯示地圖、搜尋地點。這把金鑰要開啟 Places API (New)。
2. 啟動全部元件：
   ```sh
   just demo
   ```
   這會依序啟動 PostgreSQL、套用遷移、以 `DEMO_RESET=1` 啟動後端，再啟動兩個介面與展示頁。後端的 log（`backend/.run/server.log`）要看到下面兩行：
   - `travel estimates: google (MAP_API_KEY is set)`
   - `DEMO_RESET is on`

   沒有 just 時，照 `justfile` 裡 `demo` 的步驟逐一執行。
3. 開好分頁：只要一個，展示頁 `http://localhost:5170`，投影出去的就是這一頁。另外留一個終端機視窗給 `just demo-offstage`，講者看得到、觀眾看不到。
4. 用新的瀏覽器設定檔或無痕視窗開展示頁。乘客的篩選條件會記在瀏覽器裡（7.1），Demo 的重設清不掉。

## 開演前 3 分鐘

這段不給觀眾看，或當作開場白的背景。

1. **重設**：在展示頁按「重設」兩次。兩支手機會重新載入，回到起點。
2. **啟動台下腳本**：在終端機執行
   ```sh
   just demo-offstage
   ```
   腳本會依序：
   - 替 `driver5` 選「女性友善」，並往 `driver4` 帶入的目的地出發（不顯示在展示頁上）。
   - 在背景開模擬器、按「開始模擬」，模擬車與 `driver5` 開始移動。腳本開的頁面不載入 Google 地圖，不另外用掉配額。
   - 之後一直執行，`driver5` 收到請求就自動婉拒；按 Ctrl-C 結束。它不會重設 Demo，也不會動到 `just demo` 的後端與介面。

   沒有 just 時，在 `ui/` 下執行 `node scripts/demo-offstage.ts`。
3. **`driver4` 出發**：約 30 秒後，終端機顯示「▶ 現在請 driver4 出發」。在展示頁左邊的手機上：
   - 看一眼「今天載人嗎？」：地圖畫出松山車站 → 堤頂大道一段 → 瑞光路 513 巷的真實路線，**沒有**「路線為估算」。
   - 打開「我的標籤」，確認「女性友善」已選取（選一次後會保留，重設不會清掉）。
   - 按「我出發了」，畫面換成深色的「行程中／目前沒有搭車請求」。
4. **等待提示**：約 1 分 40 秒後，終端機顯示「▶ 現在可以開始台上的 2 分鐘」。這時 `driver4` 大約在上車點前 500 公尺，`driver5` 比它更靠近上車點。

> 開場想讓觀眾看到「駕駛出發、地圖顯示行程路線」，就把第 3 步放在台上做，再接一段約 1 分 40 秒的開場白。台上的 2 分鐘從下面的 0:00 開始算。

## 台上 2 分鐘

時間是實測值：兩次預演都是 97 秒走完。下表的時間另外留了講話的時間。

| 時間 | 操作 | 畫面上看到 | 講者說 |
|---|---|---|---|
| 0:00 | 指著右邊的乘客 | 「松山車站／距離 20 公尺／最快 3 分鐘到」，時間軸上幾台車正在接近 | 「上班族到了松山車站，打開 App 就知道接下來幾分鐘有幾台車要開進內科、還有幾個空位。不用選車，平台會替他配。」 |
| 0:15 | 乘客按「今天我要搭」；在篩選中把「女性友善」設成「強制」、「不抽菸」設成「建議」；按「送出請求」 | 「正在等駕駛確認」 | 「乘客只想搭標示『女性友善』的車，這是硬條件；不抽菸只是偏好。」 |
| 0:25 | 不用操作：台下腳本替 `driver5` 自動婉拒，終端機顯示「driver5 婉拒了…」 | 乘客：「上一位駕駛無法載你，已改配下一台車。」左邊的駕駛畫面整片變黃：「有乘客要搭車／上車 松山車站／下車 瑞光路 513 巷」 | 「第一位駕駛今天不方便，平台立刻改配下一台。駕駛開車時不用看地圖，只看到上哪、下哪，一個大按鈕。」 |
| 0:35 | 駕駛按「確認」 | 乘客：「幾分鐘後到」、車牌 ABC-0004、藍色 Mazda 3，地圖上的車沿路開過來；下方小字「這台車不完全符合你的建議標籤」 | 「確認了。這台車沒有『不抽菸』，平台仍然配給它並清楚標示『已放寬』：建議條件只加分，不會讓乘客多等。地圖上的車頭跟著實際行進方向轉。」 |
| 約 1:30 | 等車開到 | 乘客：「車已到上車點」 | 「車到了。」 |
| 1:35 | 乘客按「我已上車」 | 乘客：「在瑞光路 513 巷下車」；駕駛：乘客那一列變成「在車上」 | 「上車之後，乘客只剩一個按鈕。」 |
| 1:45 | 乘客按「我已下車，結束共乘」 | 乘客：「共乘完成／路上少了一台車。」；駕駛的乘客列消失 | 「一趟共乘結束，路上少了一台車。」 |

注意：

- **「女性友善」是駕駛自己勾的標籤，沒有經過驗證**。被問到「怎麼確定」時，就說 PoC 的標籤都是自己勾選；之後會加上企業認證的標籤（REQ-009～REQ-012，Phase 2），由公司幫員工背書。
- **要說「女性友善」，不要說成「只配女性駕駛」**。系統不知道使用者的性別，也不依性別篩選，只看駕駛有沒有勾這個標籤。
- 已確認畫面的「幾分鐘後到」來自 Google 的即時路況（例如「4 分鐘後到」），但模擬車固定以時速 25 公里前進，實際約 1 分半就到。講者不要照著數字說「還要 4 分鐘」。
- 送出後約 3～5 秒，`driver5` 被腳本婉拒，左邊的駕駛畫面才變黃。

## 收尾

`driver4` 繼續沿路線開往瑞光路 513 巷，約 10 分鐘後抵達目的地（從乘客上車算起），行程自動結束（T21），左邊的手機換成「行程結束／已到達目的地／瑞光路 513 巷／這趟載了 1 位乘客」，按「好」回到「今天載人嗎？」。

2 分鐘內等不到這個畫面：可以在問答之後再切回展示頁給大家看，或事先截圖放在簡報最後一頁。

## 再演一次

1. 在終端機按 Ctrl-C 結束台下腳本。
2. 展示頁按「重設」兩次。
3. 重新執行 `just demo-offstage`，從〈[開演前 3 分鐘](#開演前-3-分鐘)〉的第 3 步做起。重設後腳本會在終端機提示「driver5 沒有進行中的行程了」，看到這句也代表要重新執行。
4. 乘客的篩選會保留上一次的「女性友善 強制、不抽菸 建議」，送出前看一眼即可。

兩次預演中，重設後再演一次都順利走完，第二次同樣是 97 秒。

## 出狀況時

| 狀況 | 現場看到 | 怎麼辦 |
|---|---|---|
| **斷網**（後端連不到 Google） | 路線預覽改用估算，並標「路線為估算」；看板、已確認畫面的時間標「估算」 | 照常演，流程完全一樣，只是時間變成估算值。可以順口說「斷網時平台改用估算，並清楚標示」 |
| **斷網**（瀏覽器也斷了） | 地圖底圖不出來；目的地無法搜尋 | 照常演：劇本只用預先帶入的目的地，不需要搜尋；地圖空白不影響操作 |
| **重設失敗** | 展示頁出現紅字「重設失敗，請確認後端有在執行。」 | 確認後端在跑（`curl http://localhost:8080/api/ping`），再按一次重設；或在終端機執行 `just demo-reset`。還是不行，就 `just backend down` 後重新 `just demo` |
| **重設後乘客顯示「連線不穩」** | 另外開著、停在請求畫面的乘客分頁一直顯示「連線不穩」 | 重新整理那個分頁。展示頁的重設會自動重新載入兩支手機，不受影響 |
| **`driver4` 一直沒變黃** | 乘客一直停在「正在等駕駛確認」 | 看終端機：台下腳本是否還在執行、有沒有「driver5 婉拒了…」。腳本停了就重新執行 `just demo-offstage`（不用重設），它會沿用 `driver5` 現有的行程並婉拒。注意模擬器會從路徑起點重新開始，車要再開一段才到 |
| **送出得太晚** | 終端機顯示「注意：driver5 已經過上車點」 | 照常演：請求會直接配給 `driver4`，跳過婉拒那段，講者略過「第一位駕駛不方便」那句即可 |
| **乘客「目前沒有可搭的車」** | 送出後立即顯示 | 通常是兩位真人駕駛都已經經過上車點，或沒有執行台下腳本、忘了讓 `driver4` 出發。按「回去看接近的車」，重設後從頭來 |
| **車一直沒到上車點** | 已確認畫面停住 | 台下腳本被關掉了，模擬器跟著停。重新執行 `just demo-offstage`（不用重設）。模擬器會從路徑起點重新開始，車約 3 分鐘後才到上車點；時間不夠就重設後從頭來 |

## 為什麼這樣安排

- **台上的駕駛用強制標籤收請求**：Go 依感受成本排序（REQ-042，design.md 4.11 媒合引擎），最近的模擬車（自動接受）通常最先拿到請求。只有台上的兩位真人駕駛帶「女性友善」，乘客設成強制後，請求就一定配給他們（ui-design 8.8）。
- **婉拒交給 `driver5`**：只有一位駕駛帶「女性友善」時，婉拒後沒有下一台符合的車，會變成「無車可配」。讓 `driver5` 早 30 秒出發、比 `driver4` 更接近上車點，請求會先配給 `driver5`；它婉拒後，改配給台上的 `driver4`，後面的上車、結束共乘、行程結束都在台上那支手機發生。
- **標籤效果演「已放寬」**：同一個請求裡把「不抽菸」設成建議。符合強制條件的兩台車都沒有不抽菸，平台照樣配給最快的車，並標示「已放寬」，正好說明「建議只加分、不讓乘客多等」的取捨（REQ-047）。不另外安排「標籤勝出」，因為那需要讓幾台車的等待時間接近，現場不好控制。
- **只用一位乘客**：一位乘客有未結束的請求時不能再送出（REQ-069）。取捨、婉拒、確認都在同一個請求裡，就不需要換乘客，也不用先結束共乘再送第二次。
- **台下交給腳本**（[#85 T18E](https://github.com/sohoffice/debugthon-carpool/issues/85)）：`driver5` 的出發、婉拒與模擬器都由 `just demo-offstage` 完成，講者不用切換分頁，也不需要另一個人。`driver5` 沒有上一趟行程（用來展示第一次使用），腳本直接透過 API 出發，目的地和 `driver4` 相同，模擬器的路徑也開得到。
